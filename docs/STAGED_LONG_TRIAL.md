# 分阶段模型继续到百万步：成功率提高到 85.8%，中途存在波动

日期：2026-09-16。沿用“前 65,536 步联合训练、之后冻结脑内连接”的路线，三个种子均从 **262,144 步继续到 1,048,576 总环境步数**。所有训练、固定节点评估及状态核验已完成。

**继续训练带来了收益：在同一批新测试地图上，平均成功率从 80.5% 提高到 85.8%，增加 5.3 个百分点。** 但过程不是单调上涨：四个节点的均值为 **80.5% → 83.5% → 80.3% → 85.8%**。平均角速度指令变化也增大，后续机器人控制应同时考虑平滑性。

## 成功、失败与控制平滑性

每个节点汇总 3 × 200 个回合。同一批 200 张地图在三个训练种子下重复评估，不是 600 张独立地图。

|总步数|成功|碰撞|超时|平均任务回报|平均角速度指令变化|
|---|---:|---:|---:|---:|---:|
|262,144|483|96|21|37.65|0.424|
|524,288|501|86|13|39.51|0.501|
|786,432|482|98|20|37.42|0.537|
|1,048,576|515|76|9|40.45|0.634|

从起点到最终模型，成功多了 **32 回合**，碰撞少了 **20 回合**，超时少了 **12 回合**。

角速度指令变化为相邻控制步角速度指令差的绝对值，单位 rad/s，先逐回合平均再汇总。该指标从 0.424 增至 0.634，约增加 **49%**；旧测试集也从 0.417 增至 0.620。它是在不同轨迹及回合长度上的汇总指标，本轮没有对动作平滑性做单独控制或优化。

## 固定验证集

验证地图沿用 5,400,000–5,400,099，共 100 张，仅用于记录趋势，没有据此挑选模型或更改超参数。

|种子|262,144 步本轮重测|524,288 步|786,432 步|1,048,576 步|
|---|---:|---:|---:|---:|
|71|81%|80%|81%|84%|
|72|85%|86%|84%|87%|
|73|83%|80%|91%|87%|
|均值|83.0%|82.0%|85.3%|86.0%|

上轮记录的起点验证均值为 83.3%；本轮重测为 83.0%。差异来自种子 73 的地图 **5,400,057**：旧记录为成功，本轮为碰撞。其余 299 个回合的结果类别一致。该差异被保留在原始记录和汇总数据中。

当前 CUDA 稀疏加法没有全局确定性保证，重复执行可能产生不同的浮点轨迹；[PyTorch 对 `index_add` 的确定性说明](https://docs.pytorch.org/docs/stable/generated/torch.use_deterministic_algorithms.html)也记录了这一限制。这里把它作为复测差异报告，未重跑并挑选更好的结果。模型和冻结权重的内容一致性另以哈希和逐字节比较验证。

## 本轮改变了什么

只增加训练预算。真实 MaleCNS 子图仍为 **4,096 个神经元、459,342 条允许连接、1,314 个下降神经元读出**。连接来自解剖数据；感觉编码、简化神经动态和二维机器人动作残差映射为前轮保留的工程建模。

脑内连接自 65,536 步后一直冻结；每个控制步仍运行脑内传播，产生神经活动。PPO 继续优化 3,960 个 actor/critic 读出参数。学习率、奖励、感觉输入、网络结构、批量与裁剪设置均沿用上轮，完整设置见[预定协议](STAGED_LONG_PROTOCOL.md)。

本轮使用完整状态续训，恢复上轮的模型、读出 Adam、未结束回合、当前观测、神经活动、回合起点标记、环境 RNG 及 Torch CPU/GPU RNG。恢复状态一致不等于 CUDA 整个后续执行逐位确定。

## 验证与算力

- **44 项测试通过**。本轮新增完整恢复测试，覆盖随机动作、跨回合重置和下一次参数更新的一致性。真实图 1,024 步流程检查也通过。
- 每个 rollout 检查脑内权重不变且没有梯度；全部新检查点的脑内连接与原联合 65,536 步模型、上轮 262,144 步模型均**逐字节一致**。
- 图位置、连接符号、输入映射、下降神经元索引及校准统计保持一致；读出权重继续变化。
- Adam 更新计数 **16,384 → 65,536**；中间两个节点为 32,768 和 49,152。
- 核心采样和 PPO 更新代码与上轮逐字一致。源模型哈希、完整恢复状态和逐地图评估对应关系均通过核验。
- 仅使用 RTX 5090 工作站 的**物理 GPU 1**及项目 Conda，没有安装新依赖。训练结束后 GPU 1 利用率为 0%，显存占用 23 MiB。

|种子|新增环境步数|纯训练耗时|峰值 PyTorch 已分配显存|
|---|---:|---:|---:|
|71|786,432|405.5 秒|405.7 MiB|
|72|786,432|406.8 秒|404.9 MiB|
|73|786,432|409.5 秒|404.9 MiB|

合计新增 **2,359,296 步**，纯训练约 **20 分 22 秒**；正式流程含验证、测试和保存约 **22 分 48 秒**。显存峰值包括训练阶段的固定节点验证，不等于整个进程显存占用。

## 结论

**这条分阶段路线继续训练到百万步，能进一步提高当前任务的平均成功率，但收益有波动，并伴随更大的角速度指令变化。** 本轮支持保留百万步模型作为更高到达率的基线，尚不能保证继续增加步数仍会提高，也没有确定收敛上限。

考虑后续移动机器人或机械臂场景，下一轮应将到达率与动作平滑性一起比较。可以单独检验更低学习率或动作变化惩罚的作用；这些改动本轮均未执行。

结果属于该真实子图上的二维仿真避障。没有评估硬件或机械臂迁移，也没有据此更换网页当前控制器。

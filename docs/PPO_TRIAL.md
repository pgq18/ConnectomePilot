# PPO 首轮试跑 · 2026-09-15

两组均完成 8,192 步训练，使用同一训练配置和独立测试场景。
果蝇组只训练动作输出策略，输入编码和 MaleCNS 连接图保持固定。

## 设备与实际开销

设备为 Apple M4、10 核 CPU、16GB 内存，macOS 26.6.2。
PyTorch 检测到 MPS 可用；本轮使用 CPU、1 个 PyTorch 线程、1 个环境，两个训练任务依次执行。
这种小型 MLP-PPO 适合使用 CPU，参见 [SB3 官方说明](https://stable-baselines3.readthedocs.io/en/master/modules/ppo.html)。

| 项目 | 距离传感器 PPO | 冻结果蝇脑 + PPO |
| --- | ---: | ---: |
| 训练交互步数 | 8,192 | 8,192 |
| 可训练参数（含价值网络） | 10,437 | 9,541 |
| 训练耗时，不含独立评估 | 2.48 秒 | 204.01 秒 |
| 训练进程峰值内存 | 277.41 MiB | 863.95 MiB |
| 触发资源限制 | 否 | 否 |

训练器每 256 步检查进程峰值内存和训练耗时，默认阈值为 1,536 MiB 和 600 秒。
内存超限会停止并保存检查点；时间预算到达时保留已有策略，并记录实际交互步数后评估。
这是进程内采样检查。上述内存数据是各训练进程的峰值，不是整台机器的总占用。

当前设备能承担这种冻结连接图的小型 PPO 训练。主要成本在全脑仿真：按本次速度估算，
果蝇组训练 100,000 步约需 42 分钟，另加评估时间；这一更长训练尚未执行。

## 训练方式

- 任务：散布障碍的二维移动机器人导航。
- 固定基础控制器，PPO 输出线速度、角速度的动作残差，经限幅后相加执行。
- 策略与价值网络均为两层 64 单元的 MLP；SB3 PPO，学习率 `3e-4`，rollout 为 512 步，batch 为 64。
- 随机种子 42；训练地图种子取自 `[0, 999999]`。
- 传感器组观测为 9 条距离射线和 5 个目标/机器人状态量，共 14 维。
- 果蝇组观测为左右 DNp01 活动和同样的 5 个状态量，共 7 维，未加入距离旁路。
- 连接图包含 166,700 个神经元和 25,582,938 条有向连接，全部冻结。

PPO 参数发生了实际更新；果蝇连接矩阵在训练前后的 SHA256 完全一致。
当前试验不包含连接权重的梯度训练，也不包含机器人硬件操作。

## 独立评估结果

评估地图种子为 `2000100–2000109`，与训练种子范围分离。
所有控制器使用相同的 10 张地图，PPO 以确定性动作执行。
本轮为散布障碍分布，和之前的绕桩评估分布不同。

| 控制器 | 到达目标 | 碰撞 | 超时 |
| --- | ---: | ---: | ---: |
| 基础控制器 | 1/10 | 9/10 | 0/10 |
| 规则避障 | 5/10 | 0/10 | 5/10 |
| 果蝇脑 + 原有手工动作映射 | 3/10 | 2/10 | 5/10 |
| 传感器 PPO，训练前 | 1/10 | 9/10 | 0/10 |
| 传感器 PPO，训练后 | 4/10 | 6/10 | 0/10 |
| 果蝇 PPO，训练前 | 1/10 | 9/10 | 0/10 |
| 果蝇 PPO，训练后 | 2/10 | 8/10 | 0/10 |

这次训练流程已跑通，短训后的收益有限。果蝇 PPO 未超过传感器 PPO，也未超过原有手工映射。
两组输入信息不同，且仅有一个训练种子、10 个测试场景，结果不足以判断生物连接图的价值。
仍需区分训练步数不足、只读出两个神经元的信息损失，以及奖励设置等因素。

## 一致性验证

- 23 项单元/接口测试通过。
- 加速实现按神经元编号累加实际放电的连接；在真实连接图的 40 个控制周期、200 个神经时间步中，
  所有膜电位、脉冲、读出和动作均与原 SciPy 实现逐位相同。
- 本机测得每个控制周期的平均神经计算从 97.97 ms 降到 24.86 ms；该数字来自本次有限输入序列。
- 重新加载两个实际策略，在测试地图 2000100 上验证了训练环境与网页控制器：
  距离 PPO 的 39 步、果蝇 PPO 的 90 步中，动作和机器人位姿完全一致，均正确结束于碰撞。

## 文件与复现

完整记录位于 `results/ppo/`：

- `rays/`、`fly/`：`policy.zip`、`initial_policy.zip`、`checkpoint.zip`、`run.json`、`evaluation.json`。
- `progress.csv` 是每次 PPO 更新的训练日志；`train.monitor.csv` 是训练回合记录，分别位于两组目录内。
- `comparison.json` 汇总两组完整记录；`backend-validation.json` 和 `playback-validation.json` 保存一致性检查结果。
- `requirements-rl.lock.txt` 记录本项目 Conda 环境的实际依赖版本。

重新进行一组独立训练，使用新输出目录保留现有结果：

```bash
${PROJECT_DIR}/.conda/bin/python ${PROJECT_DIR}/scripts/train_ppo.py --features fly --steps 8192 --rollout-steps 512 --eval-seed-start 2000200 --output ${PROJECT_DIR}/results/ppo/fly-next
```

`--features rays` 选择传感器对照；`--resume /绝对路径/policy.zip` 从已有策略和优化器状态继续训练。
续训从新回合开始，使用新输出目录；`--steps` 表示追加交互步数，实际步数会受完整 rollout 和时间预算影响。
`--max-train-seconds` 与 `--memory-limit-mib` 可调整资源预算。

网页加载 `results/ppo/rays` 和 `results/ppo/fly` 中已完成评估的模型。
可选“PPO · 距离传感器”或“PPO · 果蝇脑”，并保持场景、编号、修正强度一致进行对照。
网页运行已训练策略时不会继续学习。
